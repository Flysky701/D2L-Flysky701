## 1. 接上 6.2：为什么需要填充和步幅？

6.2 中，每次取一个局部窗口，与卷积核对应位置相乘，再求和。默认窗口每次移动一格，而且必须完整落在输入内。

例如，`8×8` 输入经过 `3×3` 卷积核，不填充、步幅为 1：

```text
每个方向可放置的位置数：8 - 3 + 1 = 6
输入 8×8 → 输出 6×6
```

连续这样卷积，空间尺寸会逐层缩小。本节增加两个控制窗口放置方式的参数：

| 参数 | 控制什么 | 直觉 |
| --- | --- | --- |
| `padding`（填充） | 在输入边界外补多少层数值 | 给窗口增加可放置的空间 |
| `stride`（步幅） | 窗口每次移动多少格 | 决定输出位置采样得多密 |

这里讨论的是高、宽的变化，通道数仍然是 1。

## 2. 填充 padding

### 2.1 `padding=1` 是什么？

当前使用 `nn.Conv2d` 的默认零填充。`padding=1` 表示上、下、左、右各补一层 0，不是四个方向总共补一层。

以 `3×3` 输入为例：

```text
原输入：             四周各补一层 0：
                     0  0  0  0  0
a  b  c              0  a  b  c  0
d  e  f       →      0  d  e  f  0
g  h  i              0  g  h  i  0
                     0  0  0  0  0
```

对 `8×8` 输入，补完边后相当于 `10×10`；再使用 `3×3` 核、步幅 1，输出为：

```text
8 + 2×1 - 3 + 1 = 8
```

所以此时 `8×8 → 8×8`。

### 2.2 修正最初的直觉

- 不填充也能利用边缘像素，但边缘像素通常参与的窗口较少；填充允许窗口部分伸出原图，让边缘位置也能形成更多输出。
- 补零没有创造新的图像信息，零是人为设定的边界值。
- 填充不一定保持尺寸不变，要结合卷积核和步幅计算。常见的 `3×3` 核、`padding=1`、`stride=1` 才是这里保持高宽不变的组合。

## 3. 步幅 stride

`stride` 是窗口每次移动的格数，不是直接设置“训练加速多少倍”。

用长度为 8 的一行、宽度为 3 的窗口说明，不填充：

```text
输入索引：0 1 2 3 4 5 6 7

stride=1 的窗口起点：0、1、2、3、4、5 → 6 个输出
stride=2 的窗口起点：0、2、4         → 3 个输出
```

步幅为 2 时，下一个起点虽然是 6，但窗口需要覆盖 `6、7、8`，索引 8 已越界，所以停止。

在二维输入中，高、宽分别按各自步幅移动。`stride=2` 表示两个方向都每次移动两格。

### 修正“步幅小就学得最多”

- 在其他条件相同的情况下，步幅较小通常产生更密集的输出位置，计算量较大。
- 步幅较大通常缩小输出、减少计算，但也可能丢失细节。实际运行速度还受硬件和实现影响。
- 输出更密集不代表一定学得更好；效果还取决于任务、数据和网络设计。
- 步幅与上一节训练中的学习率 `lr` 是不同的概念：前者控制窗口移动，后者控制参数更新幅度。

## 4. 输出尺寸怎样计算？

当前代码没有设置膨胀率，使用默认 `dilation=1`。设：

| 符号 | 含义 |
| --- | --- |
| `H, W` | 输入的高、宽 |
| `k_h, k_w` | 卷积核的高、宽 |
| `p_h, p_w` | 上下各填充的层数、左右各填充的层数 |
| `s_h, s_w` | 高度方向和宽度方向的步幅 |

```text
输出高 = floor((H + 2*p_h - k_h) / s_h) + 1
输出宽 = floor((W + 2*p_w - k_w) / s_w) + 1
```

`floor` 表示向下取整，例如 `floor(3.5)=3`。窗口放不完整的位置不产生输出。

本地代码三个配置的公式推算如下（这些是推算值，不作为本次运行实测记录）：

| 输入高宽 | 核高宽 | padding | stride | 每个方向的计算 | 输出高宽 |
| --- | --- | --- | --- | --- | --- |
| `8×8` | `3×3` | 0 | 1 | `floor((8-3)/1)+1=6` | `6×6` |
| `8×8` | `3×3` | 1 | 1 | `floor((8+2-3)/1)+1=8` | `8×8` |
| `8×8` | `3×3` | 1 | 2 | `floor((8+2-3)/2)+1=4` | `4×4` |

这里的数字型参数同时应用于高、宽。需要分别设置时，可以传入二元组，例如 `kernel_size=(3, 5)`、`padding=(1, 2)`、`stride=(2, 1)`。

## 5. 当前代码：把二维输入交给卷积层

对应 [6.3.py](6.3.py) 中的辅助函数：

```python
def comp_conv2d(conv2d, X):
    """计算卷积层的输出。"""
    X = X.reshape((1, 1) + X.shape)
    Y = conv2d(X)
    return Y.reshape(Y.shape[2:])
```

### 5.1 函数接收的是什么？

```python
Y = comp_conv2d(conv2d, X)
```

传入两个对象：`conv2d` 是创建好的卷积层，`X` 是待处理的数据。函数内的 `conv2d(X)` 才是用这个层计算输出；这里没有进行训练。

### 5.2 `(1, 1) + X.shape` 为什么不是数值相加？

当前 `X` 是二维的：

```python
X = torch.rand(size=(8, 8))
```

`torch.rand` 创建形状为 `(8, 8)`、数值位于 `[0, 1)` 的随机张量。`size=` 是按参数名指定形状。

此时 `X.shape` 为 `torch.Size([8, 8])`，可以参与元组式的拼接：

```python
(1, 1) + X.shape
# 结果相当于 (1, 1, 8, 8)
```

这里的 `+` 拼接形状，不会把元素的数值加一。前后形状分别为：

```text
(8, 8) → (1, 1, 8, 8)
           N  C  H  W
```

- `N=1`：一张输入。
- `C=1`：每张输入有一个通道。
- `H=8, W=8`：每个通道是八行八列。

`reshape` 改变形状，数值和元素总数不变：`8×8 = 1×1×8×8`。函数里的 `X = ...` 重新绑定局部变量，不会把调用处原来的二维 `X` 改成四维。

### 5.3 `Y.shape[2:]` 取出了什么？

```python
conv2d = nn.Conv2d(1, 1, kernel_size=3)
```

前两个 `1` 分别是输入通道数和输出通道数。`kernel_size=3` 表示 `3×3` 核，默认 `padding=0`、`stride=1`，因此输出形状是：

```text
Y.shape = (1, 1, 6, 6)
索引位置    0  1  2  3
```

切片 `[2:]` 表示从索引 2 一直取到最后，因此：

```python
Y.shape[2:]
# 相当于 (6, 6)
```

所以：

```python
return Y.reshape(Y.shape[2:])
```

把 `(1, 1, 6, 6)` 还原成便于查看的 `(6, 6)` 后返回。这个写法适用于当前批量和输出通道都为 1 的例子；不能直接套到多个样本或多个输出通道上，否则元素数量通常对不上。

## 6. 当前代码：循环比较三个配置

```python
X = torch.zeros(1, 1, 8, 8)
for padding, stride in ((0, 1), (1, 1), (1, 2)):
    conv = nn.Conv2d(1, 1, kernel_size=3,
                     padding=padding, stride=stride)
    print(f"padding={padding}, stride={stride}: {tuple(conv(X).shape)}")
```

- `torch.zeros(1, 1, 8, 8)` 直接创建四维全零输入，不需要再补批量和通道维度。
- 外层元组里装着三组配置。每轮把一组里的两个数分别赋给 `padding` 和 `stride`，这叫解包。
- 三轮依次是：`padding=0, stride=1`；`padding=1, stride=1`；`padding=1, stride=2`。
- `conv(X)` 计算输出；`.shape` 查看形状；`tuple(...)` 转成普通元组，便于显示。
- `f"...{表达式}..."` 是格式化字符串，会把花括号内表达式的结果放进文本。

根据公式，这部分应打印的形状是：

```text
输入形状: (1, 1, 8, 8)
padding=0, stride=1: (1, 1, 6, 6)
padding=1, stride=1: (1, 1, 8, 8)
padding=1, stride=2: (1, 1, 4, 4)
```

前面的辅助函数例子返回二维结果，`main()` 中直接查看卷积层的四维结果，所以打印形式不同。

注意：这里用全零输入是为了观察形状，不代表卷积输出的数值一定为零。`nn.Conv2d` 默认带偏置，输出数值还受偏置影响；输出形状则由输入形状和卷积配置决定。

文件前面创建随机输入、调用辅助函数和打印的代码在 `main()` 外。直接运行文件时会先执行它们，再执行文件末尾调用的 `main()`，所以会看到两组演示。若导入这个文件，函数外的代码也会执行。
